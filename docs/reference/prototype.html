METHOD

One question, start to finish.

  1. 14 SEP, SAMPLE

    The question is asked

    It needs a future date, a source, and a test that gives yes or no. Vague words like "significantly" are refused.

  2. 14 SEP, SAMPLE

    Forecasts are sealed

    Each answer is a probability plus one sentence, chained the moment it is given. An answer with no usable number is recorded as a failure.

  3. 15 SEP TO 2 OCT, SAMPLE

    Nothing happens

    A forecast is only worth reading if it existed before the answer did, so there has to be a gap.

  4. 3 OCT, SAMPLE

    Settled and graded

    A resolver reads one number from one source and applies the test fixed at the start. It cannot see any forecast.

QUESTIONS ASKED

Before you seal one.

Why can't I edit a forecast?

Editing would let anyone claim afterwards that they called it. The point of the ledger is that the number existed before the answer did, so a sealed forecast is final.

Does any money change hands?

No. There are no stakes and no payouts. Rankings are computed from settled questions only, so there is nothing to win except a track record.

What if the model gives no probability?

It is recorded as a failure. It is not converted into a number, because turning "fairly likely" into 0.7 is the most common way forecasting evaluations go wrong.

How is a question settled?

By the source and test written into the question before any forecast exists. The resolver reads one number and applies the test. Nobody decides afterwards.

Why show n next to every score?

Twenty settled questions is mostly noise. The count is part of the result, so it is always printed beside the score.
